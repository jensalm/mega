## Batch: the project page's two dialogs (implementation agent)

Cards `improve-the-new-project-dialog` and `improve-the-adopt-a-session-dialog`, each with what was settled with Michael on 2026-11-18.

### The wrapping, reproduced first

No suite covered the adopt dialog, so `checks/dialogs.mjs` began as a measurement of it as it was, at 400, 720, 1024, 1280 and 1920 pixels.
- **Every width broke, the same way.** The dialog was `min(480px, 100vw - 32px)`, so from 512px up it was 480px whatever the window. Each row's date and id took two lines, and the id, 36 characters with only hyphens to break at, split across them. At 400px the meta still took two lines, the id moving whole to the second.
- **Why "some screens".** It was not the window. A browser whose fonts run wider moves the split, which may be why it looked different on different screens.

### The register dialog's picker

- **`projects_root`** in the config, expanded from `~`, absolute or refused; unset means the home directory (`Options.ProjectsRoot`).
- **`Service.Folders(path)`** lists one folder:
  - folders only, sorted, `Git` from a `.git` there, `Registered` from the registry;
  - dot-folders left out, and a link listed only where it resolves to a folder inside the resolved root;
  - read 256 entries at a time, stopping at 2,000 folders or 50,000 entries read (`Stopped`);
  - the way up (`Parent`) offered only while the parent resolves inside the root.
- **Unlisted paths are answers.** Outside the root, missing, unreadable or relative, the reply is 200 with a `Note` and no entries. My first version answered 400, and the suite's run logged a browser console error each time a path outside the root was typed. Since that is ordinary while typing, it is a note now.
- **`validateCheckout`** expands `~`. A path typed in full registers wherever it is.
- **The dialog** (`RegisterProjectDialog`).
  - **The field** starts at the root (`~/Repos/` for Michael, `~/` by default). Its text decides what is listed: up to its last slash is the folder, after it the start of a name, so typing completes and Tab finishes it.
  - **The list** is a listbox driven from the field, with clicks and keys: Down from the field, arrows, Enter or Right in, Left or Backspace up.
  - **The name** follows the folder until edited.
  - **Two fixes the suite found.** Entering an empty folder unmounted the list and lost focus, so Left did nothing; the list now stays mounted with its notes inside. Playwright will not click an `aria-disabled` row, so the registered-folder step clicks with `force`, as a person can.

### The adopt dialog

- **Discovery** reports `held`, the sessions it left out because a conversation holds them (`Service.DiscoverHeld`; `Discover` stays for its callers).
- **The look.** `harness.Looker`, implemented in each adapter as its own history read passed through `harness.LookOf`, which takes the first and last prompt and the last reply from mapped events and bounds them: 4,000, 2,000, and the last 2,000 bytes. It is served at `GET /api/projects/{id}/look` through `Service.Look`. It writes nothing, and its text is never logged. A Go test per adapter feeds each its own recorded material: the fake shim's `messages` with `testdata/history.jsonl`, the Codex test binary's `thread/read`, and pi's `p1-and-p4.jsonl` placed in a scratch store.
- **The fake Codex** keeps threads in `threads.json` under `$CODEX_HOME`, else `~/.fake-codex`, never `~/.codex`, so `thread/list` and `thread/read` work across processes as codex's store does. No Go test runs it; the checks run it with a scratch `HOME`.
- **The page** (`AdoptDialog`).
  - **Size:** `dialog.adopt-dialog`, 1,120px wide at most and 880px tall at most, a grid whose list and look scroll inside, side by side above 760px and stacked below.
  - **Harness control:** each harness discovered as the dialog opens, for its count.
  - **Rows:** a grid of choice, preview clamped to two lines and how long ago (`zone.ago`, the exact time as title), with the id on a second line, `nowrap`, cut with an ellipsis.
- **The cost.** `probes/look/` writes synthetic sessions of 2,000 turns in scratch (Claude Code's transcript, a Codex rollout, a pi session file) and times each adapter's `Look`. The results: about 0.33 s for Claude Code (0.2 s of it the shim), 0.22 to 0.27 s for Codex with its app-server's start, and about 0.1 s for pi. The Codex run used the installed `codex` with `CODEX_HOME` in scratch; `~/.codex` was checked afterwards and nothing in it had changed.

Each writer moved beside its harness's fake: `shim/claude/fake/transcript.mjs`, `internal/harness/codex/fake/rollout.mjs` and `internal/harness/pi/fake/session.mjs`. `probes/look/gen.mjs` only calls them, and `run.sh 300` still runs.
