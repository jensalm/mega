### What was built

- **A configured path is checked** (`harness.CheckPath`). Claude's `executable` checks an absolute path before anything runs, so the SDK never meets a missing build. Codex's `FindExecutable` already stat'ed a path. Both reasons now end with advice: "install Claude Code, or set claude.executable in '…/mega.yaml', the config file mega read, to where it is". The config file is `config.Config.File`, and `Where()` says whether mega read it or only looked for it. Each harness takes `Where` in its config. A bare name keeps its old reason, since the project's `PATH` is where to look.
- **A harness's own failure has a code.** The models, launch, discovery and history calls wrap their errors as `harnessFailure`. `explain` turns one that is not a missing executable into `harness_failed` (502). Its message is the summary, "'claude' failed: <first line>; mega's log has the rest". The whole error is logged. `recordable` gives the same summary, so a launch failure's event in the history holds no stack either. `summarize` drops `at …` frames and caret lines, joins an `Error:` line when the first line is not one, and cuts at 300 characters.
- **Dialogs.**
  - **Focus.** Each dialog focuses its field after `showModal()`, by ref.
  - **The model list.** `useModels` keeps the refusal's code. An `executable_missing` refusal marks the harness "(cannot run)" in the dialog, even before the project's resolution lists it.
  - **The stale sentence** is replaced with what is true: the settings' model and effort are taken, or the launch is refused.
  - **Height.** A `dialog` has `max-height: calc(100dvh - 32px)`, scrolls, and its `.actions` are sticky at the foot.
- **First run.**
  - **Start-up and registration.** `service.New` calls `resolveAllLocked` after the fill, and `RegisterProject` calls `resolveRegisteredLocked`. Both go through `resolveStaleLocked`, which already skipped a project whose file is unapproved, changed or malformed. `TestRegistrationAndStartUpResolveInTheBackground` asserts that such a file is never resolved.
  - **The bound.** `resolveSlots` holds four slots, and the harness check takes one too. `background`, a `WaitGroup`, lets tests wait for the start-up work to settle. Several flaked without it, because a resolution finishing announces a workspace change.
  - **The harness check.** `checkHarnesses` resolves the shell in the home directory with no activation, keeps that environment, and logs one line per harness. The workspace read re-checks each harness against it (`harnesses`), so an install shows without a restart. `harness.Locator` gives the "found where" text. On the first page, "the project's PATH" reads "your shell's PATH".
  - **The page.** `FirstRun` replaces the placeholder while there is no project. Register's word appears while there is no project, and New conversation's while there is no conversation. `claudeCannotRun` uses the project's resolution, else the start-up check, and the trust notice waits on it.
  - **`--listen`.** It is a persistent flag beside `--config` and `--data`. `config.Load` takes it as a third argument, and `Validate` holds it to loopback as before.

### The cost of resolving at start-up

- **A scratch home** with a minimal profile (`/dev/shm/resolve-cost/measure.sh`): 40 projects, restarted. mega answered 37 ms after it started, and all 40 were resolved 1.2 s after that. Workspace reads meanwhile took 9 to 35 ms.
- **Michael's own profile** takes 0.16 to 0.22 s per login shell, before any activation. So a workspace of 40 projects is about 2 s of shells, four at a time, plus what each activation takes.
- **What is new.** A workspace read already started these resolutions; now they also run with no page open, as at a daemon's start.

### Gotchas

- **With no terminal, an error at start-up goes to the log file only.** The `--listen 0.0.0.0` step reads the refusal from the other mega's `mega.log`.
- **Service tests must wait for the background work.** A new rig's resolution can land mid-test and announce a workspace change. `newService` and the rigs call `svc.background.Wait()`.
- **The server's heartbeat test** now skips a `workspace_changed` frame, since the start-up check can send one first.
